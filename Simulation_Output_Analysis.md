# Packet Routing Simulator - Simulation Output & Feature Analysis

This document provides a comprehensive analysis of the simulation metrics, visual indicators, terminal trace logs, and modal outputs generated by the Packet Routing Simulator.

---

## 1. Interface and Control Panels

The interface is structured into four primary functional zones:

### A. Topology Actions & Security Panel (Left)
* **Standard / ECMP Presets:** Instantly populates either a standard 7-node mesh or a dual-path spine-leaf data center grid.
* **Interactive Editing:** Allows users to add custom routers, draw cables with custom weights, drag nodes, and click links to simulate physical severed cables.
* **Security & Threat Testing:**
  * **Simulate Rogue Router:** Designates a specific router to advertise poisoned low-cost routes.
  * **RPKI Origin Validation & Quarantine:** Enables autonomous threat detection and node isolation.

### B. Scalable Vector Graphics (SVG) Canvas (Center)
* **Visual States:**
  * Green ring: Source router
  * Amber ring: Destination router
  * Crimson hatched ring: Compromised / Rogue router
  * Dashed grey ring: Quarantined / Isolated router
  * Red dashed cable: Severed / Failed link
  * Blue link highlight: Active shortest path
  * Purple link highlight: ECMP load-balanced path

### C. Simulation Parameters (Right)
* **Routing Algorithm:** Dijkstra (Link-State / OSPF) vs. Distance Vector (Bellman-Ford / RIP).
* **Traffic Transmission Mode:** Single Packet Stream vs. Traffic Flow Burst (ECMP Load Balanced).
* **Quality of Service (QoS):** Best-Effort (DSCP 0) vs. Expedited Forwarding (DSCP 46).
* **Dynamic Network Conditions:** Congestion simulation and Split Horizon loop suppression.

### D. Metrics Scoreboard & Trace Terminal (Bottom)
* Displays real-time delivery status, metric cost, hop distance, scientific compute time, and security state.
* Interactive terminal logging hop-by-hop traversal and protocol events.

---

## 2. Scoreboard Metrics Breakdown

### A. Delivery Status
* `Delivered (Optimal)`: A single minimal-cost path was found and verified.
* `Delivered (ECMP 2 Paths)`: Multiple parallel equal-cost paths were discovered; traffic was striped across them.
* `Dropped (Rogue)`: The packet entered a compromised node without RPKI defense and was blackholed.
* `Unreachable`: All possible routes are severed or blocked.

### B. Algorithmic Compute Time
* Displayed as: `X.XX µs (1,000 runs avg)`.
* **Empirical Method:** The backend measures execution elapsed time across 1,000 full algorithm iterations on the active topology using high-resolution monotonic performance clocks. For a typical 7-node network:
  * Dijkstra: ~3.32 µs per run
  * Distance Vector: ~2.14 µs per run

### C. Security State
* `Verified Normal`: Standard topology with no malicious advertisements detected.
* `Rogue Blackhole Intercept`: Attack active; packets sucked into blackhole drop.
* `RPKI Quarantined & Rerouted`: Rogue node detected, quarantined, and bypass route established.

## 3. Scenario Output Analyses

### Scenario A: Equal-Cost Multi-Path (ECMP) Flow Burst
* **Setup:** Click **Load Multi-Path Grid (ECMP)**. Source: `R1`, Destination: `R6`. Traffic Mode: *Traffic Flow Burst*.
* **Scoreboard Output:**
  * Delivery Status: `Delivered (ECMP 2 Paths)`
  * Total Link Cost: `7`
  * Total Hops: `3 hops`
  * Compute Time: `~3.85 µs (1,000 runs avg)`
* **Terminal Trace Output:**
  ```
  [11:02:10 AM] ECMP Optimization: Detected 2 equal-cost minimal paths. Traffic flows will be load-balanced.
  [11:02:10 AM] Flow #101 dispatched on Path [R1 -> R2 -> R4 -> R6]
  [11:02:10 AM] Flow #102 dispatched on Path [R1 -> R3 -> R5 -> R6]
  [11:02:11 AM] Flow #103 dispatched on Path [R1 -> R2 -> R4 -> R6]
  [11:02:11 AM] Flow #104 dispatched on Path [R1 -> R3 -> R5 -> R6]
  [11:02:12 AM] Forwarded via R1 -> R2 (link metric: 3) [QoS: Best-Effort - +12ms queue buffer delay]
  [11:02:12 AM] Forwarded via R1 -> R3 (link metric: 3) [QoS: Best-Effort - +12ms queue buffer delay]
  [11:02:13 AM] Packet successfully arrived at destination router R6. Delivery confirmed.
  ```
* **Analysis:** The engine discovers that both Path 1 (`R1-R2-R4-R6`) and Path 2 (`R1-R3-R5-R6`) possess an identical metric sum of $3 + 2 + 2 = 7$. The 4 flows are striped across both paths in parallel, demonstrating equal-cost load sharing.

### Scenario B: Rogue Router Attack & Blackhole Drop
* **Setup:** Standard Grid. Source: `R1`, Destination: `R7`. Check **Simulate Rogue Router** with `R2` selected. Leave RPKI unchecked.
* **Scoreboard Output:**
  * Delivery Status: `Dropped (Rogue)`
  * Security State: `Rogue Blackhole Intercept`
  * Total Link Cost: `-`
* **Terminal Trace Output:**
  ```
  [11:05:01 AM] Security Warning: Router R2 is broadcasting poisoned low-cost advertisements to neighboring nodes.
  [11:05:02 AM] Forwarded via R1 -> R2 (link metric: 1) [QoS: Best-Effort - +12ms queue buffer delay]
  [11:05:03 AM] CRITICAL: Packet intercepted by Rogue Node R2. Malicious blackhole packet drop executed.
  ```
* **Analysis:** Because `R2` falsely advertised a metric of 1, the shortest path tree diverted packets away from legitimate routes directly into `R2`. Once received, the packet was blackholed and dropped.

### Scenario C: RPKI Origin Validation & Automated Quarantine
* **Setup:** Same as Scenario B, but check **RPKI Origin Validation & Quarantine**.
* **Scoreboard Output:**
  * Delivery Status: `Delivered (Optimal)`
  * Security State: `RPKI Quarantined & Rerouted`
  * Total Link Cost: `6` (routed cleanly via `R4` and `R7`)
* **Terminal Trace Output:**
  ```
  [11:06:14 AM] RPKI Origin Validation: Anomaly detected on router R2 (invalid route origin authorization).
  [11:06:14 AM] Defense Filter: Quarantined router R2. Topology recalculation initiated to isolate malicious node.
  [11:06:15 AM] Forwarded via R1 -> R4 (link metric: 2) [QoS: Best-Effort - +12ms queue buffer delay]
  [11:06:16 AM] Forwarded via R4 -> R7 (link metric: 4) [QoS: Best-Effort - +12ms queue buffer delay]
  [11:06:17 AM] Packet successfully arrived at destination router R7. Delivery confirmed.
  ```
* **Analysis:** The RPKI filter recognized the illegitimate announcement from `R2` and dynamically quarantined it. The engine computed the next best valid route via `R1 -> R4 -> R7`, successfully delivering the payload without human intervention.
